CONSTRAINTS & QUALITY CRITERIA

Create one complete slot game per Skill execution.

Do not create a casino company or multi-game casino platform.

Avoid generic descriptions.

Provide concrete JSON schemas.

Provide exact mathematical formulas.

Provide code templates.

Provide exact prompt templates.

Provide exact file names.

Provide exact interfaces.

Provide exact state transitions.

Provide exact test cases.

Provide measurable performance targets.

Provide measurable acceptance criteria.

Use current, source-backed research.

Clearly separate facts, assumptions, recommendations, and legal-review items.

Use studios such as Pragmatic Play, Hacksaw Gaming, Nolimit City, Push Gaming, Relax Gaming, and similar companies only as general market references.

Do not clone protected games, characters, artwork, names, sounds, paytables, reel strips, or proprietary mechanics.

Use generic mechanic terminology unless licensing rights are confirmed.

Ensure that the slot is original.

Ensure that the mathematical model is fixed, versioned, hashed, and reproducible.

Ensure that the outcome is server-authoritative.

Ensure that the visual client cannot determine or modify the result.

Ensure that normal, quick, turbo, skip, and autoplay modes do not alter the mathematics.

Ensure that Feature, Super Feature, and Ultimate Feature tiers are mathematically distinct.

Ensure that all feature tiers have separate simulation results.

Ensure that the UI is fully immersive but remains readable.

Ensure that every animation has timing, skip, recovery, reduced-motion, and low-performance rules.

Ensure that the game supports mobile portrait, mobile landscape, tablet, desktop, and ultrawide layouts.

Ensure that accessibility does not depend only on color, audio, flashing, or haptics.

Ensure that autoplay and feature buys are controlled by jurisdiction policy.

Ensure that no feature has unbounded mathematical liability.

Ensure that no feature can enter an infinite loop.

Ensure that money values use integer minor units or exact fixed-point values.

Do not use binary floating-point for settlement values.

Use Bun for TypeScript and JavaScript tooling.

Use uv for Python environments, dependencies, and execution.

Use PixiJS as the default renderer unless another technology is clearly justified.

Use a deterministic development round provider only for development and testing.

Clearly separate development outcome generation from production Remote Game Server integration.

Include game-state recovery and committed-outcome replay.

Include mathematical, state-machine, UI, animation, accessibility, performance, and recovery tests.

Do not claim regulatory certification without actual certification evidence.

Do not implement player-specific RTP, behavioral odds, loss-chasing logic, hidden payout adjustment, deceptive win displays, or misleading near-miss messaging.

Do not stop after research or concept generation.

Continue through mathematics, schemas, UI, animation, assets, audio, code architecture, testing, and final packaging.
