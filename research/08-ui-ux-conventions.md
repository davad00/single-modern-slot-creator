## Findings

### 1. HUD anatomy — always-visible information

The universal current-gen HUD kit is: spin button, bet selector, balance display, total-bet display, win display, autoplay control, settings/burger menu, info/paytable button [observed][S20][S22][S23]. Regulatory and standards pressure hardens parts of this into hard requirements:

- **Balance, total bet, current win must be persistently visible during play.** No regulator words it exactly this way, but it falls out of AGCO 11.1.1 ("meaningful and accurate information to enable informed choices") and UKGC RTS 7 display rules; every current-gen release from Pragmatic, Hacksaw, Nolimit, Push, Relax and Peter & Sons shows all three at all times in both orientations [mandatory-in-effect][S1][S10][S30]. Pragmatic Play places financial information in the lower-left corner next to the "i" (rules/paytable) button [observed][S30].
- **Net position (UK):** UKGC RTS 2E — all gaming sessions must clearly display the customer's net position (total winnings minus total losses since session start) in account currency; in force for slots since 31 Oct 2021 and extended to other casino products 17 Jan 2025 [mandatory, GB][S4][S5][S31]. This is normally operator-fed data rendered in a game-frame HUD strip; the game client must reserve space for it and accept it via the operator wrapper API [observed][S31].
- **Elapsed time (UK):** RTS 13C — elapsed session time "should be displayed for the duration of the gaming session", starting when the game opens or when play begins, displayed in seconds, minutes and hours [mandatory, GB][S2]. RTS 13A additionally requires a clock or elapsed-time display whenever a full-screen client hides the device clock [mandatory, GB][S2].
- **Reality checks (UK):** RTS 13B — player-configurable on-screen reality check (elapsed-time display) that must be acknowledged before it disappears; no new funds committed until acknowledged; the next game in any sequence must not start until acknowledged; the dialog should offer exit/logout and a link to account history [mandatory, GB][S2]. The game client must expose a pause/interrupt hook so the operator wrapper can inject this overlay between rounds [inferred from S2 — RTS is operator-facing, but the interrupt point must exist in the game].
- **Spin state, autoplay state, turbo state** must be visually unambiguous (button state machine, counters on autoplay, distinct toggle glow on turbo) [observed across all six reference studios][S20][S30]. Where autoplay is active, remaining-spins count is shown on or beside the spin button in every current Pragmatic/Hacksaw/Push release [observed][S30].
- **Feature-buy price** is shown persistently on the buy panel/button as an x-bet multiple and as currency at the current bet [observed][S24][S25].
- **Max win** is surfaced (a) on the intro/splash screen ("win up to 10,000x"), (b) in the paytable/rules, and by Nolimit City also in lobby marketing ("150,000 xBet MAX WIN") [observed][S24][S30]. Several jurisdictions require the max-win statement in the rules; the UK requires that displayed potential prizes be accurate and attainable (RTS 3D; AGCO 11.1.3 "attainable on any given Bet unless clearly stated") [mandatory][S3][S10].
- **RTP:** UKGC RTS 3C — house edge, RTP percentage or probability information "must be easily available before the customer commits to gamble"; guidance says use the average theoretical RTP and place prominent links on game selection pages or within games [mandatory, GB][S3]. MGA: game rules must be displayed in full no more than one click away from the page on which the game can be played; downloaded clients must present rules before the first wager [mandatory, MT][S11]. AGCO: paytable awards, game rules, feature info and automatic-selection behaviour must be available before committing a bet; theoretical payout percentage must be disclosed [mandatory, ON][S10]. Practical convention: RTP lives on the last page(s) of the paytable and in the rules text, per operator-configured value when multiple RTP profiles ship [observed][S30].

### 2. Layout systems — portrait, landscape, tablet, desktop, ultrawide

- **Portrait-first is the industry default.** Hacksaw Gaming built mobile-first/portrait-native from day one; the majority of slot sessions are on smartphones; "mobile-first" means designing the smallest screen first, not shrinking desktop [observed][S20][S25]. Portrait layout: reels centred in the upper ~55–65% of the screen, win/balance/bet strip directly under or over the reels, spin cluster in the bottom third ("thumb zone") [observed][S20][S22].
- **Thumb zone:** spin, bet stepper, autoplay live in the bottom third of a portrait phone screen; frequency-of-use ordering, generous spacing to prevent mis-taps (a spin button adjacent to bet controls causes accidental stake changes) [recommended][S20][S22]. Left-handed mode (mirrored control placement) is offered by some studios [observed][S22-adjacent, tagged observed via S-landscape sources].
- **Landscape/desktop:** reels centred, controls either in a bottom bar (info · −/+ bet · autoplay · spin · turbo) or, very commonly in current-gen releases (NetEnt-descended convention used by Pragmatic, Relax, Push), a vertical control stack on the right side of the reels with spin largest at centre-right; burger menu and sound bottom-left or top-left [observed; the named "right-side stack" pattern is not formally documented — closest documented statement is "beside the reels" placement rationale][S22][S23][S-landscape searches, see register S21/S23].
- **Tablet:** landscape layout with enlarged touch targets; tablets take the desktop/landscape composition rather than the phone-portrait one [observed][S20].
- **Ultrawide/desktop letterboxing:** full-scene games extend background art to fill 21:9; HUD stays anchored to a central 16:9 safe zone. Studios plan UI scaling for 16:9, 18:9 and 21:9 at production start [observed][S21].
- **Foldables** are an emerging edge case (compact ↔ dual-screen transition) [observed][S20].
- **Orientation change:** both orientations supported with live relayout (no forced reload); games show a brief re-layout transition. Where a game is single-orientation, a "please rotate your device" overlay is used because programmatic lock is unavailable on iOS (see §9) [observed][S16].

### 3. Control placement and state design

Every interactive control ships with at minimum idle / pressed(hover) / disabled states; production practice is three states per element planned at asset stage [observed][S21]. Current-gen norms per control:

- **Spin button:** largest control on screen; states: idle (pulsing subtle), pressed, spinning (morphs to Stop/skip where legal), disabled (insufficient balance / menu open / regulatory inter-round gap), autoplay-active (shows remaining count + stop glyph), turbo-armed variant [observed][S22][S23][S30]. UK: the button must be released and re-pressed for each cycle; holding must not trigger new spins (RTS 14D guidance) [mandatory, GB][S1]. Desktop spacebar = spin; hold spacebar = turbo-repeat in Pragmatic titles (must be disabled for GB builds) [observed][S30].
- **Stop/skip:** the spin button becomes Stop during reel spin; skips result presentation without altering outcome. UK RTS 14E prohibits any control that reduces time-to-result (turbo, quick spin, slam stop) — exemption for bonus/feature games where no additional stake is wagered [mandatory, GB][S1].
- **Autoplay:** dedicated button beside spin opening a sheet: number of spins (10/25/50/75/100 presets), loss limit, single-win limit, stop-on-feature. Banned entirely in GB (RTS 8, slots since 31 Oct 2021; all online products from 17 Jan 2025) and prohibited for slots in Ontario [mandatory gates][S4][S5][S10-secondary]. Where legal, several jurisdictions require loss limits and stop-at-any-time (cf. AGCO OLG standard 10.29 minimums: player picks bet and number of auto-bets, can stop any time, each result shown for a reasonable time, dollar/time limits) [mandatory, ON-OLG][S10b].
- **Quick spin / turbo:** settings toggle plus sometimes a persistent lightning icon; two tiers common (quick = shortened spin, turbo = near-instant). Feature-flag OFF for GB [mandatory][S1]; visible-on state must persist across sessions and be clearly indicated [observed][S30].
- **Bet selector — two dominant patterns:** (a) inline stepper: −/+ around total-bet readout (Hacksaw, Nolimit); (b) bet sheet/panel: tap total bet opens a modal with preset chips, min/max buttons, and (legacy Pragmatic) coin-value + coins-per-line controls collapsing to total bet [observed][S25][S30]. Modern releases overwhelmingly expose a single "total bet" number; coin-value selectors are legacy and should only appear when the math model needs them [observed][S20][S30]. Gesture betting (swipe up/down) exists but is novelty, not convention [observed][S20]. AGCO 11.1.7: games must not encourage increasing the bet [mandatory, ON][S10]; UKGC RTS 14A prohibits encouraging raised stakes/chasing losses [mandatory, GB][S1] — so no "bet more to unlock" prompts, and max-bet buttons must not be visually privileged.
- **Balance / bet / win displays:** text meters in a slim strip (portrait: below reels above spin cluster or at very bottom; landscape: bottom bar or corners). Win meter counts up (tick-up with tiers, §7); balance updates only at settlement [observed][S23][S30]. All money as formatted currency in the player's account currency; both cash and (rarely, legacy) coin display [observed][S30].
- **Feature-buy button:** persistent panel on the left side of the reels in landscape / above-left of reels in portrait, showing themed art + price in x-bet and currency; tap → confirmation dialog with price restated and Confirm/Cancel (two-step commit is universal) [observed][S24][S25]. Multi-tier buys (Hacksaw: standard/super/mystery; Nolimit: 3/4/5-scatter entries at e.g. 100x/400x/2000x in San Quentin) present a vertical list with per-tier price, and Nolimit caps max bet (e.g. $4) when the most expensive tier is selected — an explicit liability-management UI behaviour [observed][S24][S25]. Jurisdiction gate: hidden entirely in GB (banned 2019) and NL; restricted in ON; available in most .com and several US markets [mandatory gates][S25][S26].
- **Enhanced-chance / ante-bet toggle (e.g. a +25% stake "xBet"-style control):** placed adjacent to the bet selector, ON state visibly changes total bet and trigger-odds text; unavailable in GB (stake-increase incentive) [observed + mandatory gate, GB][S24][S25]. Never copy the trademarked "xBet" name (see research/12-market-patterns-ip.md §6) [mandatory internal rule, CONVENTIONS §9.10].
- **Settings / burger menu** (see §6), **sound/music toggles**, **fullscreen control** (desktop only; see §9), **paytable/info button**: one tap from the base HUD at all times [recommended; MGA one-click rule makes it effectively mandatory for rules][S11][S30].

### 4. Paytable, rules, feature-guide presentation

- **Paged overlay** (horizontal swipe pages or vertical scroll) covering: symbol pays at current bet (values recomputed in currency when bet changes — dominant convention), feature explanations with illustrations, scatter requirements per tier, ways/lines diagrams, buy-feature prices, max win, RTP, malfunction-voids clause, version string [observed][S23][S30]. AGCO 11.1.2 requires all of it available before first bet; MGA requires full rules ≤1 click away; UKGC RTS 3A/3C/3D require rules, RTP/probability and prize information easily available before committing [mandatory][S3][S10][S11].
- Paytable opens as an overlay that never blocks settlement and is disabled mid-presentation only if the jurisdiction requires acknowledgement first [observed; aligns with CONVENTIONS §4.4 "UI states are overlays"].
- **Scatter requirements** (3/4/5+ → feature/super/ultimate) must be explicit in the paytable with trigger counts and, where required (e.g. ON probability-disclosure thresholds), odds statements [mandatory, ON for extreme odds >1:17M top award][S10].
- **Accuracy rules:** no "due/overdue/ready-to-hit" implications (AGCO 11.1.3(d)); displayed outcomes attainable at any bet unless stated; multi-language paytables must be consistent (AGCO 11.1.10) [mandatory, ON][S10].
- **Intro/splash info screen:** Pragmatic-style pre-game screen with 2–4 feature panels, max-win figure and a volatility meter, plus "don't show again" toggle [observed][S30]. This is the natural home for the max-win and RTP-profile statement in unregulated-display markets [recommended].

### 5. Feature-buy UI specifics (numbers)

- Price norms: standard feature buy 50–100x total bet; super/premium tiers 200–500x; extreme tiers up to 2000x+ (Nolimit San Quentin 3/4/5-scatter buys at 100x/400x/2000x); Hacksaw range observed 80x–300x [observed][S24][S25].
- UI invariants: price always restated in the confirmation dialog; balance check before enabling; buy disabled during autoplay (where autoplay legal), during active feature, and below min balance; post-buy the triggering spin plays out visibly (players must see the scatters land) [observed][S24][S25].
- Spending-velocity is the regulatory concern (100x buys every ~2 min at $1 ≈ $3,000/hr vs $300–600/hr base play) — expect more jurisdictions to gate it; treat as a per-jurisdiction feature flag with most-restrictive default per CONVENTIONS §9.6 [observed rationale][S25][S26].

### 6. Settings & burger-menu contents

Canonical burger menu (bottom-left or top-left; Pragmatic uses three-line icon lower-left) [observed][S30]:

| Item | Notes |
|---|---|
| Sound FX toggle + Music toggle | separate toggles are the norm; master volume slider optional [observed][S30] |
| Quick spin / turbo toggle | jurisdiction-gated [S1][S30] |
| Battery saver / low-performance mode | reduces animation intensity & FPS; Pragmatic ships it in selected games (won "Innovation in Mobile" 2020) [observed][S30] |
| Intro screen on/off | skip splash next load [observed][S30] |
| Ambient/screen-shake/reduced-motion | growing; reduced-motion should also honour OS `prefers-reduced-motion` (§10) [recommended][S8-adjacent] |
| Game history | committed-round list with per-round detail/replay; required by most regulated markets and expected by MGA/ON audits [mandatory in regulated markets — verify per jurisdiction][S10b] |
| Game rules / paytable / feature guide | duplicate entry point to the "i" button [observed][S30] |
| Bet settings | legacy coin-value UI lives here when present [observed][S30] |
| Clock/session info, RG links | operator-frame territory in GB; in-game elsewhere [S2][S31] |
| Version / RTP footer | game name, version, RTP profile displayed in rules footer [observed][S30] |

### 7. Immersion techniques — full-scene worlds vs framed reels

- **Two composition families.** (a) Framed-reels: ornamental theme-integrated frame over a painted background (classic; still dominant for low-complexity titles). (b) Full-scene: reels embedded in a diegetic environment — symbols sit on stone, wood, stage scaffolding; no hard frame; environment extends edge-to-edge (Push Gaming's Turn It Up! places the player at a rock concert with lights and crowd; Peter & Sons integrates protagonist journeys through mythical realms directly into the reel area) [observed][S27b][S29][S24-adjacent]. Full-scene is the current-gen premium convention and the skill's default for "immersive world" briefs [recommended].
- **Multi-layer backgrounds + parallax:** 3–5 depth layers (sky/far, mid, near, reel plane, foreground occluders) with parallax on device tilt/pointer and slow ambient drift; parallax moves background layers for depth perception [observed][S29]. Foreground environmental elements (vines, embers, crowd silhouettes) overlap the reel edges to sell depth [observed][S29].
- **Ambient animation & reactive lighting:** idle loops (flags, water, fireflies), lighting states that shift with game state (base → anticipation → feature); win events cast light/colour onto the environment [observed][S29][S27b].
- **Character-on-stage reactions:** a persistent character beside/above reels reacting to wins (celebration), near-misses (lean-in) and idle time; documented as an engagement device — "character reactions (celebrating wins, frowning at losses)" create emotional connection and help players parse outcomes faster [observed][S29]. Regulatory caution: reactions must not celebrate LDWs (below-stake returns) in GB (RTS 14F) and must not imply outcome likelihood (AGCO 11.1.3(d)) [mandatory][S1][S10].
- **Feature-world transformations:** entering `feature`/`super_feature`/`ultimate_feature` swaps the entire scene (background, reel frame, music layer, lighting), not just a banner — tier differentiation must be material in presentation per CONVENTIONS §9.3 [observed pattern; internal rule].
- **Camera motion & screen shake:** slow push-ins during anticipation, snap zooms on big wins, shake on high-impact lands — all with configurable amplitude caps and full disable under reduced-motion (§10) [observed][S29][recommended caps: shake ≤ 8 px amplitude / ≤ 400 ms, [inferred] — no published numeric standard exists; derived from reduced-motion/vestibular guidance in S8b].
- **Particles, trails, glows, shaders:** win-line particle bursts, symbol-trail effects on cascades, glow pulses on scatters, shader effects (heat haze, god rays, chromatic pulse on max win). All must have `reducedMotion` and `lowPerformance` variants per CONVENTIONS §9.8; flash rate ≤ 3/s (WCAG 2.3.1) [mandatory][S8b].
- **Seamless transitions:** crossfade/portal transitions between base ↔ feature with audio-synced stingers; skippable per animation-event contract; every transition needs a recovery policy (reconnect mid-transition must land on committed state) [observed + internal rule].
- **Win presentation tiers:** count-up meters with escalating celebration (small→max per CONVENTIONS §4.3 thresholds 5/15/40/80×); big-win sequences are interruptible (tap to collect instantly) in all six reference studios [observed][S29][S30]. GB: returns ≤ stake get no celebratory audio/visual at all — only total display, brief winline show, brief balance-transfer sound (RTS 14F guidance) [mandatory, GB][S1].

### 8. Loading UX, first interaction, audio unlock

- **Canonical sequence:** themed splash (logo + art) → progress bar with percentage → bar morphs into a bottom-centre **Play/Continue button** → (optional jurisdiction/intro info screen) → game [observed convention documented in slot-art production guides][S23][S33]. The continue gate is not just branding: it captures the **user gesture that unlocks audio** (below) and provides the point for jurisdiction acknowledgements [observed + technical requirement][S13][S14].
- **Progressive loading:** load core interface first (reels, base symbols, HUD ~ first 3–8 MB), stream hi-res/feature/big-win assets in background; games are commonly 20–100 MB+ total; goal is playable in seconds on 4G [observed][S20]. Loading screens display hints/feature teasers; animated bars are perceived as faster than static [recommended][S33].
- **Audio unlock:** Chrome (since M71, 2018) and all modern browsers create `AudioContext` in `suspended` state before user activation; call `context.resume()` inside the first click/tap/keydown handler; Chrome auto-resumes when (interaction has happened) ∧ (`start()` called). Detect via `context.state === 'running'`. Cross-origin iframes (game portals!) need autoplay permission delegated by the embedding operator page [mandatory-technical][S13][S14][S15]. Convention: the Play/Continue button doubles as the unlock; a "start muted?" choice appears in some studios [observed][S14].
- **Persistence:** intro screens and splash tips offer "don't show again"; reduced re-entry friction for repeat sessions [observed][S30][S33].

### 9. Fullscreen, safe areas, notch, orientation — exact platform behaviour

- **Fullscreen:** `requestFullscreen()` works on desktop browsers and Android Chrome/Firefox; **iPhone Safari has no element Fullscreen API** — games run in the normal viewport and rely on scroll-away-URL-bar/PWA installs; iPad supports element fullscreen [mandatory-technical][S16][S18]. Convention: fullscreen toggle shown on desktop only; hidden on iOS [observed][S30].
- **Safe areas:** requires `<meta name="viewport" content="...viewport-fit=cover">`; otherwise all `env(safe-area-inset-*)` = 0 and Safari letterboxes landscape. Apply insets via `env(safe-area-inset-top/right/bottom/left)`; read into JS/canvas via CSS custom properties + `getComputedStyle` (no direct JS API). Magnitudes: Dynamic Island phones report 59–62pt side insets in landscape vs 44–50pt on notch phones; home-indicator bottom inset in portrait ≈ 34pt [mandatory-technical][S18]. Gotchas: insets give zero margin beyond system UI — add buffer; landscape `safe-area-inset-top` reports 0 but keep ≥20px buffer at the top edge; devices without notches degrade gracefully (env() invalid → skipped) [recommended][S18].
- **Rule for HUD:** interactive controls never inside inset regions; decorative full-scene art extends behind notch/island; bottom control bar padded by `max(env(safe-area-inset-bottom), 16px)` [recommended, derived][S18].
- **Orientation lock:** `screen.orientation.lock()` supported Chrome Android (since v38, 2014) and Firefox Android (since v144, Oct 2025), requires fullscreen first; **not supported by Safari at all** (Safari 16.4 added only `type`/`angle`/`onchange`; MDN compat corrected — `"lock" in screen.orientation === false` on iOS) [mandatory-technical][S16][S17]. Fallbacks: support both orientations natively (preferred, and the market norm), or CSS media-query rotate prompt ("please rotate your device") on iOS [observed][S16].
- **Resolution scaling:** render at `devicePixelRatio` capped (commonly 2) with dynamic resolution under low-performance mode [observed practice; inferred detail — cap value varies per studio].

### 10. Accessibility — WCAG 2.2, EAA, game-specific guidance

- **Legal driver:** European Accessibility Act (Directive (EU) 2019/882) in force **28 June 2025**; applies to online gambling as e-commerce services, including non-EU operators targeting EU players and B2B suppliers up the chain; compliance benchmark is WCAG 2.1 AA (via EN 301 549); pre-existing service contracts may run unmodified until at latest 28 June 2030 (Art. 32(1)) [mandatory, EU][S12]. One legal analysis holds that surrounding flows (login, menus, payments) are clearly in scope while game content itself is a grey zone — treat the whole game UI as in scope to be safe [recommended][S12].
- **Target size:** WCAG 2.2 SC 2.5.8 (AA, Oct 2023): pointer targets ≥ **24×24 CSS px** or pass the 24px-diameter spacing-circle test; exceptions: equivalent control, inline, user-agent default, essential. WCAG 2.5.5 (AAA): **44×44 CSS px**, no spacing escape. Apple HIG: 44×44 pt; Material: 48×48 dp [mandatory AA / recommended AAA][S8][S9]. Skill rule (CONVENTIONS §9.7): ≥44px for all HUD touch targets — i.e. we build to AAA/Apple/Material level, comfortably above the AA floor [internal mandatory].
- **Contrast:** HUD text ≥ 4.5:1 (SC 1.4.3 AA; CONVENTIONS §9.7); non-text UI components/graphical objects ≥ 3:1 (SC 1.4.11); check symbol legibility against busy backgrounds with CVD simulators (Color Oracle: protan/deutan/tritan) — red reads darker to protans [mandatory/recommended][S8][S27][S28].
- **Colour independence:** no essential information by a fixed colour alone — symbol families must differ by shape/icon, not only palette; duplicate status indicators with icons/text/patterns (Game Accessibility Guidelines; Xbox XAG 102) [recommended][S27][S28].
- **Reduced motion:** honour OS `prefers-reduced-motion` via `window.matchMedia('(prefers-reduced-motion: reduce)')` AND provide an in-game toggle; "reduced ≠ none": replace parallax/zoom/shake with opacity fades and shortened durations; keep near-zero durations (e.g. 0.01 s) rather than 0 so completion events still fire; maps to WCAG 2.3.3 (AAA) and 2.2.2 [recommended, AAA][S8b]. Every animation event carries a reducedMotion variant (CONVENTIONS §9.8) [internal mandatory].
- **Flashing:** ≤ 3 flashes/second, always (WCAG 2.3.1 A — seizure safety); applies hard to win celebrations and lightning-style feature intros [mandatory][S8b].
- **Text scaling:** support 200% text zoom without loss (SC 1.4.4); in-canvas text should use a UI scale factor; minimum rendered body text ~16 CSS px, meter labels ≥ 12 px with high contrast [mandatory AA for DOM text; [inferred] for canvas-rendered equivalents — WCAG applies to web content, canvas games conventionally mirror it].
- **Population rationale:** ~15% of people have a disability, rising to ~20% among casual gamers [observed][S27b].

### 11. Haptics

- `navigator.vibrate()`: supported Chrome/Edge/Opera/Samsung on Android; **not supported iOS Safari (ever) or Firefox ≥129 (removed)**; ~77% global support; requires user activation (Chrome blocks pre-interaction calls) [mandatory-technical][S19]. iOS workaround via `<input type="checkbox" switch>` haptic quirk worked iOS 17.4–26.4 but **Apple patched it in iOS 26.5** — do not depend on it [observed][S19].
- Convention: haptics are optional, default-on where supported, toggle in settings; map `haptic.light|medium|heavy` (CONVENTIONS §4.3) to vibrate patterns (e.g. 15 ms / 30 ms / [40,30,60] ms [inferred defaults — no published standard; typical values from web-haptics libraries]) and no-op gracefully elsewhere with visual/audio fallback [recommended][S19].

### 12. Spin timing & presentation-speed law (UI consequences)

- GB (UKGC RTS, in force 31 Oct 2021 for slots): **RTS 14D** min 2.5 s per slot game cycle + release-and-re-press start; **RTS 14E** no turbo/quick-spin/slam-stop (bonus games without extra stake exempt); **RTS 14C** no simultaneous multi-game play; **RTS 14F** no celebration of returns ≤ stake; **RTS 8** autoplay banned; from 17 Jan 2025: **RTS 14G** min 5 s for non-slot casino games, plus net-position & elapsed-time display extended to all casino [mandatory, GB][S1][S4][S5].
- Ontario: autoplay for slots prohibited; no simultaneous slots; rules/paytable/RTP disclosure pre-bet; probability caps (top award ≤ 1:17M others ≤ 1:34M unless disclosed); min theoretical RTP 85% every bet configuration (land-based EGD standard; internet standards analogous) [mandatory, ON — internet-standard numbering to be verified against Registrar's Standards for Internet Gaming directly][S10][S10b].
- Malta: min RTP 85% (lowered from 92%, 2021 Player Protection Directive amendment); rules ≤1 click away [mandatory, MT][S11].
- Germany (GlüStV 2021): 5 s min spin, €1 max stake, no autoplay [mandatory, DE][S25 — secondary; verify against GGL primary text, flagged in Uncertainties].
- UI consequence: the spin-state machine must support a jurisdiction-configurable **minimum round duration** and **inter-round lockout** during which the spin button is disabled/greyed with no held-button repeat; presentation modes are flags per CONVENTIONS §9.6 [mandatory][S1].

### 13. Network, error, recovery, edge-case states

- **Network status indicator:** subtle connectivity glyph; on degradation, non-blocking toast; on loss mid-round, blocking "reconnecting…" overlay with spinner and elapsed indicator [observed convention; no formal standard — [inferred] from studio practice and RGS integration guides].
- **Reconnection/recovery:** on resume, re-fetch committed outcome manifest and seek presentation to `resumePointer` instantly (no re-spin theatre); regulated markets require the committed result be honoured and shown [mandatory in regulated markets; mechanism per CONVENTIONS §7].
- **Errors:** modal with plain-language message, error code, round id, and "malfunction voids all pays and plays" per rules text; unrecoverable errors return to operator lobby via wrapper callback [observed][S10-adjacent].
- **Insufficient balance:** spin disabled + inline message; deposit shortcut only via operator wrapper (in-game deposit prompts risk breaching RTS 14A "encourage to continue" in GB) [mandatory caution, GB][S1].
- **Game history / round replay:** accessible from menu; per-round detail (bet, win, timestamps, feature steps); replay renders the committed manifest [mandatory in most regulated markets — per-jurisdiction verification item].
- **Data-saver mode:** optional reduced-asset profile (skip hi-res atlases, static backgrounds); pairs with battery-saver toggle [observed, emerging][S30][S20].

## Uncertainties & legal-review items

1. **AGCO Registrar's Standards for Internet Gaming (current numbering).** My §12/§13 Ontario internet-gaming claims (autoplay slot ban, no simultaneous slots, LDW rules) rest on the land-based EGD standards + secondary summaries; the fetched "iGaming Standards" page was the superseded OLG document (removed April 2022). Legal review must pull the live Registrar's Standards for Internet Gaming and map exact standard numbers before shipping ON-flagged output.
2. **Germany GlüStV 2021 specifics** (5 s spin, €1 stake, autoplay ban) came from secondary sources only in this pass — verify against GGL/Glücksspielstaatsvertrag primary text. NOTE (2026-08 update): the €1 stake is now the statutory default only — the GGL implemented tiered €1/€3/€5 stakes effective 2026-07-01; see research/05-jurisdiction-rules.md §2 for the verified detail and the bet-ladder consequence (runtime `maxStakeMinor` override, not a baked ladder).
3. **Netherlands (KSA) in-client RTP display**: secondary sources say there is no explicit RTP-display mandate; verify against Besluit/Regeling kansspelen op afstand before asserting in jurisdiction-policies defaults.
4. **UK feature-buy ban legal basis**: widely reported as banned since 2019, but it derives from UKGC positions on stake-increase incentives (LCCP/RTS 14A reasoning) rather than a single named "bonus buy" clause — legal review should confirm the precise instrument before the compliance-review template cites it.
5. **EAA applicability to in-game content** (vs surrounding operator flows) is legally unsettled; we adopt the conservative reading (whole game UI in scope) [S12].
6. **"Right-side vertical control stack" landscape convention** is universally visible in current releases but not formally documented anywhere found; tagged [observed] from market inspection, no citable spec.
7. **Numeric defaults for screen-shake caps, haptic pattern durations, DPR cap** are [inferred] — no published standards exist; values chosen from vestibular-safety guidance and common library defaults.
8. **iOS haptic switch quirk** status is a moving target (patched 26.5 per ios-haptics README); re-verify at build time; never ship a dependency on it.
9. **RTS 8 exact current wording** — RESOLVED (2026-08 follow-up): live UKGC page fetched (published 2021-02-02, last updated 2025-01-21). RTS 8A aim: "To make clear that auto-play cannot be offered for online gaming." Requirement: "The gambling system must require a customer to commit to each game cycle individually." Sole stated exception: "This requirement does not prohibit offering functionality to automatically post blinds in peer-to-peer poker." A change note confirms former provision 8C has come into force and its panel was removed. [S34]
10. **Reality-check rendering responsibility** (operator wrapper vs game client) varies by RGS integration; the game must expose the inter-round interrupt hook, but which side draws the dialog needs per-integration confirmation.

## Design implications for the Skill

Concrete rules and defaults for downstream authoring agents. Encode in `client-template/`, `config/device-profiles.json`, `config/jurisdiction-policies.json`, `templates/game-design-document.md` and `prompts/ui-ux.md`.

### D1. HUD contract (all layouts)
- Always-visible: balance (currency), total bet (currency), win meter (currency, blank/0 idle), spin button with full state machine, settings entry, info/paytable entry. Portrait: meter strip directly below reels; spin cluster centred in bottom third. Landscape/desktop: right-side vertical stack (spin largest, autoplay above, bet below) OR bottom bar; pick per concept but keep spin ≥ 96 px diameter desktop, ≥ 72 px mobile (well above the 44 px floor).
- All touch targets ≥ 44×44 CSS px (CONVENTIONS §9.7; = WCAG 2.5.5 AAA, Apple 44pt; exceeds the WCAG 2.2 AA 24px floor). Minimum 8 px clearance between adjacent controls; never place bet-stepper flush against spin.
- Reserve a 24 px-high top strip (or bottom on desktop) for operator-injected regulatory UI: session clock, net position, RG links. Expose `hudApi.setRegulatory({netPositionMinor, elapsedSeconds, clockText})`.
- HUD text contrast ≥ 4.5:1; non-text control affordances ≥ 3:1; body text ≥ 16 CSS px, meter labels ≥ 12 px.

### D2. Spin-control state machine (design every state)
`idle → pressed → spinning(→stop/skip affordance if policy.slamStop) → resultPresenting(skip) → lockout(jurisdiction minRoundDuration) → idle`; plus `disabledInsufficientBalance`, `disabledOverlayOpen`, `autoplayActive(count)`, `turboArmed`. Button must require release-and-re-press (no hold-repeat) whenever `policy.holdToRepeat=false` (GB: always).
- Defaults in `spin-presentation.json`: normal round ≥ 2.8 s presentation; GB profile: `minRoundDurationMs: 2500` hard, `turbo: off`, `quickSpin: off`, `slamStop: off`, `autoplay: off`, `feature buy: off`, `enhancedChance: off`, `ldwCelebration: none`. UNKNOWN jurisdiction inherits the GB-style most-restrictive set (CONVENTIONS §9.6).

### D3. Bet selector
Default: single total-bet stepper (−/+) with long-press acceleration OFF (avoid accidental stake ramps) + tap-to-open bet sheet with preset chips (min, 0.20, 0.50, 1, 2, 5, 10, …, max from config), Min/Max buttons, and current-bet highlight. Coin-value UI only if math model demands it. Bet changes disabled mid-round. Never visually privilege Max Bet; no prompts to raise stakes (RTS 14A / AGCO 11.1.7).

### D4. Paytable & rules
Overlay, swipe/scroll pages, order: (1) features & scatter tiers with trigger counts 3/4/5+, (2) buy options + prices (where enabled), (3) symbol pays **recomputed in currency at current bet**, (4) lines/ways diagram, (5) general rules, malfunction clause, max win statement, RTP % per active profile, game + math version footer. Reachable in ≤ 1 tap from base HUD (MGA rule); available before first bet; content generated from `paytable.json`/`features.json` so it can never drift from math.

### D5. Feature buy & enhanced chance
Left-of-reels panel (landscape) / above-reels chip (portrait) with themed art, price in x-bet + currency. Tap → modal listing tiers (map to `feature/super_feature/ultimate_feature`), each with price and short description → Confirm/Cancel; restate price on confirm. Disable when balance < price, during rounds, and when `policy.bonusBuy=false` (GB/NL hidden entirely, not greyed). If the top tier costs > 500x, cap max bet while it is selected (Nolimit-style liability cap) and note the cap in rules.

### D6. Settings / burger menu (canonical contents)
Sound FX · Music · (Quick/Turbo spin, gated) · Battery-saver/low-perf mode · Reduced motion (also auto-honour `prefers-reduced-motion`) · Screen-shake off/low/full · Intro screen on/off · Haptics on/off (hidden where unsupported) · Data-saver (optional) · Game history · Game rules · Paytable · Feature guide · Left-handed mode (optional) · version/RTP footer. Persist all toggles in localStorage keyed by game slug.

### D7. Loading & first interaction
Sequence: (1) instant lightweight splash (logo, < 300 KB inline), (2) determinate progress bar with % over themed art + one rotating feature hint, (3) bar morphs into bottom-centre **Continue/Play button** — this tap is the audio-unlock gesture (`AudioContext.resume()` inside the handler; verify `state === 'running'`; silent-safe if not), (4) optional intro info screen (features, max win, volatility meter, "don't show again"), (5) game ready. Budget: interactive core ≤ 8 MB / ≤ 5 s on 4G; stream feature/big-win/audio assets in background with per-bundle retry. Support delegated autoplay permission for cross-origin iframe embedding.

### D8. Fullscreen / safe areas / orientation
- `viewport-fit=cover` mandatory; pad interactive HUD by `env(safe-area-inset-*)` with a floor of 16 px bottom and 20 px top in landscape; let scene art bleed behind notch/island; read insets into the canvas layer via CSS custom properties.
- Support BOTH orientations with live relayout (market norm; also sidesteps missing iOS lock). Desktop-only fullscreen toggle; on Android offer fullscreen+`screen.orientation.lock()` wrapped in feature detection (`'lock' in screen.orientation`); on iOS never attempt lock; if a concept is single-orientation, ship the rotate-device overlay.
- Device profiles (`device-profiles.json`): phone-portrait, phone-landscape, tablet, desktop, ultrawide; ultrawide = desktop layout + extended background, HUD anchored to central 16:9.

### D9. Immersion defaults (full-scene composition)
- Default composition: full-scene world, no hard reel frame; 4 background layers (far/mid/near/foreground-occluder) with parallax factors ~0.05/0.15/0.3/1.2 of camera motion [inferred defaults]; ambient idle loops on ≥ 2 layers; reactive lighting states per game state (base/anticipation/feature tiers).
- Character-on-stage optional module: idle / win-small / win-big / anticipation / feature-enter reaction sets; reactions never fire on LDW when `policy.ldwCelebration = none`; never imply "due to hit".
- Each feature tier transforms the world (background swap + lighting + music layer + reel-frame variant) — material presentation difference per tier is a hard rule (CONVENTIONS §9.3).
- Camera: anticipation push-in ≤ 4% scale over ≤ 1.2 s; big-win snap zoom ≤ 8%; screen shake default amplitude 6 px, 250 ms, max 8 px/400 ms, all zeroed under reduced-motion [inferred caps].
- Particles/trails/glow/shaders all defined as animation events with `reducedMotion` + `lowPerformance` variants (CONVENTIONS §9.8); global flash budget ≤ 3 flashes/s enforced at review (WCAG 2.3.1).
- Win tiers per CONVENTIONS §4.3 (5/15/40/80×, max); every celebration skippable (tap-to-collect); GB profile downgrades any return ≤ stake to no-celebration presentation.

### D10. Accessibility gates (validation-report checks)
(a) all targets ≥ 44 px; (b) HUD text contrast ≥ 4.5:1, controls ≥ 3:1; (c) symbol set distinguishable in protan/deutan/tritan simulation — shape/icon per family, never colour-only; (d) reduced-motion variant exists for every animation event and OS preference is honoured; (e) flash ≤ 3/s; (f) UI scale supports 200% text; (g) any DOM shell (menus, rules) passes WCAG 2.1 AA (EAA/EN 301 549 exposure from 2025-06-28).

### D11. Haptics
`haptic.light/medium/heavy` → `navigator.vibrate(15)/vibrate(30)/vibrate([40,30,60])` behind feature detection + settings toggle; no-op with visual/audio fallback on iOS/Firefox; never gate gameplay on haptics.

### D12. Edge/failure states (all must be designed, not defaulted)
Reconnecting overlay (spinner + elapsed + "your result is safe" copy) → recovery seeks committed manifest to `resumePointer`; error modal with code + round id + malfunction clause + lobby-return callback; insufficient-balance inline state (no in-game deposit upsell); orientation-change relayout under 300 ms without state loss; low-performance mode auto-suggested when FPS < 30 for 5 s [inferred heuristic]; game-history screen rendering committed rounds with step replay.

### D13. Jurisdiction-policy → UI flag map (minimum set in `jurisdiction-policies.json`)
`autoplay`, `quickSpin`, `turbo`, `slamStop`, `bonusBuy`, `enhancedChance`, `minRoundDurationMs`, `ldwCelebration (none|smallOnly)`, `rtpDisplay (rules|paytable|both)`, `netPositionDisplay`, `elapsedTimeDisplay`, `realityCheckHook`, `maxWinStatementRequired`. GB preset: autoplay=false, quickSpin=false, turbo=false, slamStop=false, bonusBuy=false, enhancedChance=false, minRoundDurationMs=2500, ldwCelebration=none, netPositionDisplay=true, elapsedTimeDisplay=true, realityCheckHook=true. UNKNOWN = GB preset.
